Features

The terminal is obvious. The composer is the point.

xterm.js

A real terminal

The same renderer VS Code uses. ANSI rendered as emitted — the standard "palette is for UI, not output" carve-out.

Composer

Multi-line shell, in a proper editor

CodeMirror 6 with shell highlighting. Paste at the prompt without sending Enter, or paste + run.

Snippet library

Save commands, tag them, find them later

Aux pane on the left: search, filter chips, list. Click a snippet → loads into the composer.

portable-pty

A real PTY

Spawns $SHELL (or /bin/sh), wires stdin/stdout/stderr through Tauri's event channel.

Persistent draft

Composer never auto-clears

Paste, see the error, edit, paste again. Iteration is the whole loop.

Tauri · Rust

Native Linux

One shell per window. No tabs, no splits. AppImage and .deb at first release; in-app updater wired.

Principles

What this isn't.

No tabs, no splits. One terminal per window. Open another window for another shell.
No SSH manager. Use your shell's SSH. There's no connection profile UI.
No themes, no profiles. One look, locked. No per-session config to drift across machines.
No env mangling. Spawns $SHELL with your environment. Nothing injected, nothing rewritten.
Install

Build it for now.

No public binary yet — terminal hasn't cut its first release. Once it does, AppImage and .deb will live on the GitHub Releases page and the in-app updater handles upgrades.

In the meantime, build from source:

Build from source

# clone
git clone https://github.com/krill-software/terminal
cd terminal

# install & build
pnpm install
pnpm tauri build

# resulting binary
./src-tauri/target/release/krill-terminal
